# 4장 응용 — CONTEXUS 꾸민 공부 기록 판별기

> 4장 2층 신경망으로 **"이 공부 기록은 진짜인가, 꾸민 것인가"**를 맞히는 모델을 설계 → 학습 → 평가까지 해 본다.
> 데이터는 `make_dummy.py`가 만든 **가짜 기록**. 실제 사용자 기록은 쓰지 않는다.

## 파일
| 파일 | 내용 |
|---|---|
| `make_dummy.py` | 더미 기록 만들기 (`load_dummy()` = 책의 `load_mnist`와 같은 모양) |
| `design.ipynb` | 실습 (빈칸 채우기) |
| `design_solutions.ipynb` | 풀이 |

## 설계 진행표 → 이번에 정한 것
| # | 단계 | 이번 선택 |
|---|---|---|
| ① | 문제 정의 | 답 = **확률** `[진짜, 꾸밈]` 두 칸, 소프트맥스 |
| ② | 입력 | 기록 한 묶음 → 숫자 8칸 (아래 표) |
| ③ | 정답 | 더미라 우리가 정함. 실제로는 가장 어려운 부분 |
| ④ | 모델 | `TwoLayerNet(8, 10, 2)` · 매개변수 112개 · 수치 미분 2000번 (약 40초) |
| ⑤ | 평가 | 정확도보다 **오탐률**(성실한 사람을 꾸몄다고 함) |

## 입력 8칸 = 앱이 기록해 둘 값 목록
| 이름 | 뜻 | 중요도(섞었을 때 떨어진 정확도) |
|---|---|---|
| `paste_ratio` | 붙여넣기로 들어온 질문 비율 | +0.020 |
| `typing_speed` | 질문 입력 속도 | +0.019 |
| `interval_cv` | 질문 간격이 들쭉날쭉한 정도 | +0.015 |
| `followup_ratio` | 꼬리 질문 비율 | +0.014 |
| `dwell_sec` | 쪽마다 머문 시간 | +0.010 |
| `page_match` | 질문이 그 쪽 내용과 맞는 정도 (⭐ 실제로는 임베딩 필요) | +0.006 |
| `revisit_ratio` | 앞 쪽으로 돌아간 비율 | +0.005 |
| `study_days` | 공부한 날 수 | +0.001 ← 혼자서는 쓸모없음 |

## 결과 (풀이 노트북, seed 0)
- 아무것도 안 하는 모델("전부 진짜"): 정확도 **0.80**
- 학습한 모델: 시험 정확도 **0.985** · 오탐 **0.010** · 놓침 **0.035**
- ⭐ 오차역전파(5장)로 바꾸면 같은 학습이 **0.44초** (수치 미분 약 43초)

| 판정 문턱 | 오탐률 | 놓침률 |
|---|---|---|
| 0.50 | 0.010 | 0.035 |
| 0.70 | 0.007 | 0.045 |
| 0.90 | 0.000 | 0.085 |
| 0.99 | 0.000 | 0.280 |

→ 오탐을 줄이면 놓침이 늘어난다. **문턱은 모델이 아니라 사람이 정하는 결정.**

## 배운 것
- 정확도 80%는 공짜로 나온다 (꾸밈 비율 20%) → **기준선**부터 확인
- 단위가 다른 입력은 **표준화** (시험 데이터도 훈련의 평균 · 표준편차로)
- 한 칸만 섞어서 정확도가 얼마나 떨어지는지 보면 무엇이 중요했는지 안다 (순열 중요도)
